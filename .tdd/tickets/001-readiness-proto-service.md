## Scope

Create the protobuf contract and Rust module skeleton that every later readiness
ticket builds on. This ticket wires plumbing only — it does NOT compute real
mastery, real scores, or real coverage. Those are tickets 002–005.

**Key codebase fact:** `web/rslib/proto/rust.rs:72` discovers `.proto` files by
scanning the `proto/` directory. There is no list of proto files to register.
Service traits are auto-generated by `web/rslib/rust_interface.rs`. Model the
service impl on `web/rslib/src/stats/service.rs`.

Files:
- `web/proto/anki/readiness.proto` (new)
- `web/rslib/proto/src/lib.rs` — add `protobuf!(readiness, "readiness");`
- `web/rslib/src/lib.rs` — add `pub mod readiness;`
- `web/rslib/src/readiness/mod.rs` (new)
- `web/rslib/src/readiness/service.rs` (new)

Proto shape:

```proto
service ReadinessService {
  rpc TopicMastery(TopicMasteryRequest) returns (TopicMasteryResponse);
  rpc ThreeScores(ThreeScoresRequest) returns (ThreeScoresResponse);
}
service BackendReadinessService {}
```

`TopicMastery` message: `topic`, `cards_total`, `cards_with_history`,
`avg_retrievability`, `graded_reviews`, `mastery`, `covered`, `state`
(enum: `UNKNOWN` | `INFERRED` | `MEASURED`).

`Score` message: `estimate`, `low`, `high`, `confidence`, `coverage_pct`,
`evidence_count`, `last_updated`, repeated `reasons`, `abstaining`,
repeated `missing_evidence`.

`ThreeScoresResponse`: `memory`, `performance`, `readiness` — three `Score`s.
